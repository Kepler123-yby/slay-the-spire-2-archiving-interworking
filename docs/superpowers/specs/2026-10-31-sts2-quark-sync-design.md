# 杀戮尖塔 2：Mac / Windows 夸克存档互通

日期：2026-10-31。状态：用户已授权按一般设想先实现和验证 Mac，Windows 提供可执行验证文档。

## 用户明确提出的目标

- 游戏是《杀戮尖塔 2》，macOS 与 Windows 两端均通过 Steam 启动。
- 用户已确认两端使用同一个 Steam 账号；第一版只处理该账号在两端的互通，不提供跨账号迁移。
- 两台电脑不一定在同一地点，也不一定同时开机。
- 使用用户已有的夸克网盘作为云端中转。
- 登录、上传、下载、备份和恢复都由本工具负责，不能以要求用户手动搬运网盘文件作为完成结果。

## 已知情况与未知情况

仓库当前没有产品代码。本机存在 `~/Library/Application Support/SlayTheSpire2/steam/<账号>/`，包含账号层 `profile.save`、`settings.save`，以及 profile1、profile2、profile3。profile1/saves 下实际发现 progress.save、prefs.save、history 及备份文件。本机根目录存在 Mod 配置，说明有 Mod 使用痕迹；不能由此断定当前使用 Mod，也未确认 Mod 存档路径。

Windows 候选路径为 `%APPDATA%/SlayTheSpire2/steam/<账号>/`，需要 Windows 实测。目录存在不等于游戏能成功读取跨平台复制后的存档，后者必须单独验收。

夸克官方仓库公开了授权、上传、下载等命令文档；README 当前标注支持 macOS 和 Windows WSL，不支持 Windows 原生。没有进行登录授权或真实云传输，不宣称 Windows 原生接入已可用。

## 建议采用的产品范围（由开发方提出）

做一个中文桌面工具，两端体验一致。第一版由用户主动点击“上传本机进度”或“下载并应用云端进度”，不要求到夸克客户端手动处理文件。首次登录允许打开系统浏览器完成夸克官方授权，返回后由工具接管传输。无需提供密码或粘贴 Cookie。

首次设置选择本机 Steam 账号、游戏档位和设备名称。多账号不猜测，多档位分别同步。上传后另一台电脑之后上线即可获取；不要求局域网、服务器或双端同时运行。

第一版覆盖角色解锁、长期进度、历史记录和已落盘的进行中对局；联机对局仅传递本机已有文件，不承诺迁移其他玩家状态。跨平台兼容性以实测为准。Mod 存档需要识别并独立分组；无法识别时不写入该组，明确告知尚不支持。工具不安装或同步 Mod。

第一版不做静默后台自动覆盖、游戏内注入、进度字段合并、跨版本格式转换、公共分享链接或多网盘支持。云端全部为账号私有文件。

## 技术选择与首要可行性验证（开发方选择）

建议 Electron + TypeScript：利用桌面运行时提供跨平台文件访问、窗口与网络任务。无本地 HTTP 服务，不暴露任意文件操作给页面；文件读写、网盘调用只在主进程进行。渲染进程隔离，IPC 仅提供受限业务动作。精确依赖版本、视觉布局、打包工具由实施阶段选择。

必须先完成夸克接入验证，再投入完整界面。优先评估官方 Node CLI/SDK 能否作为受管理子进程在 macOS 和 Windows 原生运行，不执行上游全局安装脚本，不要求 Windows 用户安装 WSL、Bash 或 Node。需要核实许可、分发方式、授权对独立应用的适用范围，以及是否依赖 Agent 专有环境。

若官方工具不能适配，仅在存在可合法使用的正式授权接口和应用凭据时实现原生适配器；不冒用其他应用身份，不将提取第三方签名密钥当作正常集成。浏览器网页登录兼容方案可研究，但不能预先声称可行。没有可用的原生路线时，应明确报告接入阻碍和具体可选方案，不把模拟传输、WSL 或手工搬文件包装成完成。

接入验证通过标准：两端原生环境完成授权、创建专用目录、上传测试文件、枚举、下载、SHA-256 校验、重启后复用授权及过期处理。使用测试文件，禁止先拿真实存档实验。当前开发主机是 Mac；没有 Windows 环境时只能报告 Windows 验证待完成，不能靠单元测试宣称通过。

## 存档选择与隔离

每条同步流绑定游戏、Steam 账号、档位、原版/Mod 分组。云端目录建议 `STS2-SaveSync/<账号>/<档位>/<分组>/`。不得跨账号自动写入。缺失目录时由用户选择或确认新建，不扫描并上传整台电脑文件。

同步单位为一个档位完整的已验证游戏存档集合，保持相对路径与原始字节；不按单文件时间戳拼接进度。文件范围必须在实施阶段通过本机样本和游戏行为核实。包括当前对局与历史；缓存、日志、Mod 配置、重放缓存和机器显示/输入设置默认不传。

账号级 profile.save 的作用尚需验证：若跨档位共用，须列入账号级协调与备份，不能把它与任意一个档位随意配对覆盖。未知文件先列出待识别，不静默声称完整同步。导入清单必须展示实际范围。不能为了省事复制整个 SlayTheSpire2 根目录。

## 上传、下载与版本关系

每个版本使用唯一 ID，附设备 ID、UTC 时间、同步流身份、父版本 ID、完整文件清单、文件大小和 SHA-256。时间仅供展示，不用来决定谁覆盖谁。云端保存不可变快照，不反复覆盖唯一 latest.zip。

上传前确认游戏未运行，执行文件稳定性检查，读取前后哈希一致才产生快照。游戏进程状态无法可靠确认时禁止应用存档，给出关闭游戏后重试提示。上传本身不改动游戏文件。

快照包完成上传并下载验证后才发布独立完成标记。枚举时仅展示具备完成标记且清单、包均有效的版本；断网留下的残缺对象不能成为可应用版本。进度报告区分本地打包、上传、云端校验和已发布。

本机记录上次同步的版本和本地内容哈希。单一云端后继且本地未改动时可以正常下载；本地和云端都变化、初次配对双方已有进度、离线两端分别推进或存在多个云端分支时，都显示冲突并由用户选一份完整存档。分支检测依据父子关系；没有父版本的本地进度保守处理。相同内容可去重，删除文件由完整清单表达。

用户选择一份后，先保留双方版本和本地备份，再生成记录已处理分支的解决版本。并发上传通过不可变分支保留，不依赖网盘提供事务锁。任何重试都不覆盖已有快照或自动删除分支。第一版不自动清理云端历史；空间不足直接报告。

## 应用与恢复

下载先到暂存区，完成包哈希、逐文件哈希、大小与文件类型检查。拒绝绝对路径、上级目录、符号链接、重复或大小写冲突路径、异常展开体积，限制文件数和解压总量。

真正写入前再次检查游戏状态与本地内容是否变化；变化则返回比较步骤。备份目标整个被管理存档集合，记录事务日志，再用同盘暂存和替换提交。单次文件重命名不能当作多文件原子事务。中途失败自动回滚；启动时检测未完成事务并恢复后才允许新任务。成功后逐文件校验，并排除目标中已被版本清单删除的被管理文件，防止旧对局复活。设置和范围外文件不受影响。

恢复备份与普通导入走相同检查及事务路径。备份保留且不静默自动清理；空间不足停止写入，先让用户处理空间。每次成功应用才更新本机同步基线。

## 与 Steam 云及游戏版本的关系

首次启用引导两台电脑关闭该游戏的 Steam 云存档，用户在工具内确认完成后才允许写入；不直接编辑 Steam 配置。工具不宣称能阻止 Steam 之后重新覆盖。首次选择前先分别保留两端原始进度，禁止自动认定某端更新。

尽可能记录游戏版本、Steam 分支与构建信息；不同平台的构建标识可能不同，不能仅凭构建 ID 不同断定存档不兼容。可确认游戏内容版本或分支不一致时禁止直接应用并提示先更新至相同版本。无法读取可比较版本时明确标为未知，需要用户确认两端版本一致。Mod 分组需匹配环境；不承诺不同 Mod 集合之间可读。

## 账号与故障处理

夸克授权结果留在本机；优先系统凭据存储。日志、界面、诊断导出与仓库都不能包含 Token、Cookie 或密码。退出登录清除本工具保存的凭据，但保留存档和备份。

只访问本功能的专用网盘目录，不浏览或修改其他用户资料，不创建公开分享，不清理用户其他文件。授权过期回到官方登录；网络失败保留任务与原存档，展示可重试原因；接口返回业务失败不能因进程退出码为零被当作成功。

## 交付与验收

交付源代码、中文使用说明、开发启动方式、构建配置、Mac 与 Windows 各自的打包路径。最终目标是用户无需开发环境即可使用的应用；签名/公证和真实 Windows 构建验证分别报告，不把源代码打包配置当作已发布安装包。

验收包括：两端原生夸克测试文件往返；真实存档在备份后从 Mac 到 Windows、再从 Windows 回 Mac 被游戏识别；长期进度、历史、当前对局的实际覆盖范围；两个离线分支不会自动互相覆盖；损坏包、过期授权、断网、磁盘不足和写入中断不损坏原存档；游戏运行时拒绝写入；原版与 Mod 组不混用。业务测试用临时目录与合成存档，真实用户数据只用于明确的最终联调。

如果只能在 Mac 完成测试，应写清已完成与未完成项，保留 Windows 实机验证清单；整体跨平台目标仍未验收，不宣称全部完成。
