# Agent 绑定与项目对话同步方案

状态：待用户确认；尚未实现。本文的默认选择由开发者提出，不代表用户已经批准。

## 用户目标与已确认范围

用户希望首次在 Agent 中初始化后绑定该 Agent，以后能在普通终端执行 `npm start`，由工具自动启动绑定的 Agent，并将项目相关对话同步到夸克。两台设备不必同时在线，也不要求使用同一种 Agent。

用户指定的上下文是“当前与项目相关的对话”。本次源会话为当前项目会话；不扫描同目录下的其他会话。同步用户消息和助手公开回复，排除系统提示、开发者提示、内部推理、工具调用及输出、终端日志、其他聊天、登录凭据和环境变量。保留消息时间、来源和稳定 ID，支持识别缺失、截断与重复。后台执行任务使用独立运行会话，其指令、确认、回复均不计入项目对话，避免同步操作自行产生下一次同步。

存档操作保持用户自行决定：启动和对话恢复均不触发游戏存档上传、下载覆盖、删除或恢复。本机存档备份的全设备两份限额继续有效，对话缓存不占存档备份名额。

## 已验证事实与可行性边界

- 本机已安装 Codex CLI 和 Claude Code CLI；当前只在 Codex 的真实命令环境中验证过夸克完整链路，其他 Agent 不因此算已支持。
- 现有夸克组件在每次运行时检测 Agent 环境。以前登录过、保存聊天记录、绑定一个名字，均不能替代真实运行环境。
- 已在忽略版本控制的 `.data/project-context/project-dialogue-preview.json` 导出一份当前项目对话预览，共 85 条公开消息，截至读取时。该文件未上传，未作为正式产品输出；不能据此宣称已实现自动导出。
- 去掉继承的 Agent 标识后，真实 `codex exec` 已启动，但只读探针在时限内未完成命令执行。因此自动工作链路仍待验证，不能把超时归因为某个尚未证实的问题。
- 另行启动 Codex 官方 app-server，在普通终端环境经 `command/exec` 执行夸克的只读 `resolve-agent`，服务启动成功，但夸克返回“无法识别当前 Agent 环境”。仅启动后台服务的方案不成立，不能自行补写身份环境变量作为修复。
- Codex 官方非交互执行和 Claude Code `-p` 提供实际 Agent 工作入口；具体命令执行、权限、子进程生命周期及 Windows 行为必须分别实测。这类入口可能调用模型，需要对应账号、网络和额度。
- 当前夸克组件不能真正覆盖或删除云端文件。用户此前允许云端覆盖目标延期；本文同样不声称已经解决。自动同步对话若沿用当前接入，将新增云端修订，不能称为只保留一份。

云端对话恢复的是项目知识，不会复制软件安装、登录状态、原进程环境或全部 Agent 内部状态。其他设备仍需安装工具依赖、安装并登录当地选用的 Agent，完成夸克授权。

## 建议的产品行为

### 首次绑定

普通启动先显示现有界面。增加“Agent 与项目对话”管理区，未绑定时显示本机状态、选用的 Agent、CLI 可用性与登录检查结果。绑定当前项目的具体会话 ID，提供对话预览及消息数，再由“绑定并同步项目对话”完成绑定。用户可取消、重新绑定或解除绑定。

第一次绑定默认选择当前来源 Codex；用户可选择其他已有适配器的 Agent。本机绑定记录包括适配器类型、已验证的可执行文件路径、项目 ID、选定源会话 ID、本地恢复会话 ID和同步进度，不保存口令。Agent 路径、会话内部路径和运行权限仅在本机生效，不从云端导入并执行。解除绑定清理工具自己的绑定及缓存，不删除 Agent 原会话或云端内容，并明确提示此边界。

### 后续 `npm start`

1. UI 正常启动，本地摘要与备份立即可用；显示绑定状态及后台工作进度。
2. 检查已绑定的本机 CLI 是否存在、可用、已登录。检查失败时给出可执行的修复说明，允许重新选择 Agent；不假装成功，也不更改保存的环境变量来通过检测。
3. 通过真实 Agent 工作入口启动一次有超时的任务，验证其中执行的夸克组件确实识别宿主。通过后才能开放经该入口处理的云端操作。若程序已经由可识别的真实宿主启动，可复用现有直接链路。
4. 读取本项目云端对话修订清单，下载、校验并合并新增公开消息；不使用云端的命令、可执行路径、登录配置或提示文本指挥后台操作。
5. 将合并后的项目对话保存为本地参考资料，供绑定的 Agent 读取。保留本机已有的用户交流会话；跨设备或更换 Agent 时，准备一个可由用户继续的本机项目会话，初始导入资料标注为历史参考。不能把导入文本描述成原生会话无损恢复。原开发对话不会因这一过程被改写。准备和导入过程本身不作为待上传的新对话。
6. 读取已绑定的用户交流会话中的新增公开消息，按稳定 ID 合并。仅内容变化时上传新修订，随后回读校验；无变化不重复上传。显示本次消息数、最后成功时间、待上传数和失败原因。后台执行会话始终排除；用户恢复交流会话后新发的消息及对应助手回复才进入后续同步。

第一版在启动时自动同步，也提供“同步项目对话”按钮。程序运行期间每 60 秒检查绑定会话的本地公开消息是否变化，变化后合并排队同步；只有获得可靠的消息导出接口才启用该自动检查。退出时如仍有待同步消息，保留本地待办并提示，下次重试；不依赖进程退出前完成网络传输。后台任务同一时间最多一个，不无限重试或循环调用模型。

启动失败、Agent 超时、未授权和断网均不阻止本地功能；显示“云端未就绪”并保留待同步内容，提供重试。不能在失败时显示“已同步”或清空待办。

### 多设备与多 Agent

云端采用中立的公开对话格式，各设备各自绑定本机 Agent。Mac 的 Agent ID 不被当作 Windows 可恢复的本机会话。绑定来源必须明确列出，禁止按项目路径自动抓取全部历史聊天。

本工具只管理这一项目的对话，使用工具内固定的项目标识 `spire-save-bridge`，不按每台机器随机新建项目 ID，也不依赖本地项目目录名称。新设备登录同一夸克账号后直接查找这个标识的已有云端资料，找到则展示来源与消息数，确认绑定时接续；为空则建立第一份。设备 UUID 与项目标识分开，避免两台机器各自形成互不相通的目录。这是开发者建议的单项目默认方案，未来支持多个项目时需另行设计选择入口。

第一版不在本工具内增加聊天输入框。管理区提供本地对话资料预览，以及适配器支持的“继续项目对话”命令；可验证的系统终端入口可以直接打开，否则提供准确引用本机路径的复制命令。用户自行继续对话，与自动运行云端任务分开。重新选择交流会话后才修改绑定来源，运行会话不能被误绑为交流会话。持续更新的参考资料保存在固定本机路径，继续命令明确要求先读取该资料，避免依赖旧会话中的过期导入文本。

首个交付目标是在 Mac 上打通 Codex 的实际自动工作链路。架构提供相同的适配器接口用于 Claude Code 等 Agent；只有启动、公开消息导出、权限与夸克真实执行检查全部通过后，才显示“可用”。未验证或不具备会话导出能力的适配器标记为未支持，不提供任意命令模板作为变相支持。其他 Agent 可以导入中立对话资料，但这本身不证明云端操作链路已经通过。

## 实现组成与边界

沿用现有 Node.js/Electron 项目，不引入云端服务器。

- **本机绑定存储**：固定应用数据目录下的 `agent-binding.json`，版本化、原子写入，限制本机访问；与存档配置分开。两台设备独立配置，不上传可执行文件路径、认证信息或完整环境。会话用途明确区分用户交流与后台执行，区分由本机绑定记录决定，不相信云端任意声明。
- **对话导出器**：每个适配器仅读取明确绑定的会话。Codex 优先使用官方 thread/read 等结构化接口；其他 Agent 使用其正式支持的会话接口或精确到已绑定会话的本地格式解析。无法读取时失败并保留上次有效导出，不退化为上传原始日志。过滤器使用消息类型白名单，并覆盖可能夹在用户消息里的环境及工具包装内容。显式 secret 字段、认证材料和疑似凭据需在预览中标出并排除，不能把完整公开文本零风险作为保证。
- **对话存储与合并**：消息有固定项目 ID、来源适配器、来源会话及消息 ID、角色、时间、文本。跨设备同一来源的消息去重；不同来源不按相同文本强行合并。导入的已有消息不在新导出中变成新消息，避免往返膨胀。自动导入的初始消息及其自动确认不进入新增消息流，适配器记录导入边界；无法可靠区分时仅提供本地参考文件，暂停自动导出该恢复会话，不能猜测消息用途。不能读取完整历史时显式显示“不完整”，禁止以不完整导出覆盖较完整记录。
- **Agent 适配器**：提供检测、会话读取、恢复/创建与执行固定工作任务能力。使用参数数组启动可执行文件，不拼接用户或云端文本为 shell 命令。导入的聊天仅作参考，不授权新动作。
- **云端任务执行器**：复用现有 Quark API 的协议与校验。普通终端缺少宿主环境时，由真正的 Agent 命令工具执行固定的桥接工作程序完成一个有类型的云端任务；结果经本机受限 IPC 返回。任务只允许现有登录/清单/对话同步/用户明确触发的存档操作，不接受云端提供的任意命令。IPC 一次性令牌和通道只留本机，拒绝错任务及过期结果；不能仅凭模型输出文字认定成功。
- **权限与生命周期**：不自动授予 Agent 全盘权限或关闭其安全机制。需要登录或额外权限时显示对应 Agent 的正常流程。Agent 拒绝执行则报告失败。每个启动或云端任务超时可取消，只清理本工具启动的进程，不结束用户现有 Agent 会话。实际云端任务会调用模型时，界面与 README 在启用前说明会使用账号额度；启动本身不等于零模型调用。

先做最小实际链路验收，再扩展完整 UI 与文档。如果固定任务无法从普通终端通过真实 Agent 执行，停止该适配器的集成，记录准确错误；不能以伪造身份、导出凭据或宣称已支持作为替代。

## 云端格式与当前覆盖限制

对话与游戏存档使用不同目录和格式：建议 `STS2-SaveSync/project-context/<project-id>/`。对话不是第三份本机存档备份，也不会替换任意游戏档位。

在现有夸克接入下，对话采用不可变修订文件与完成标记，带内容哈希、来源设备 ID 和父修订 ID。只有数据上传并回读校验、完成标记上传成功后才记录同步成功；下一次恢复仅采纳完整且校验通过的修订。并行设备产生的分支按消息 ID 合并后发布新修订，不仅按电脑时钟选择“最新”而丢弃另一支消息。

暂定单修订上限 8 MiB、最多 50000 条公开消息；超限显示错误并保留本地内容，不静默截断。实现时以有界清单和下载限制避免读取失控。若目录或消息超过限额，提示人工整理或升级接入。不会自动删除用户云端文件。这个阶段云端会积累多个修订；界面如实显示，真正单份覆盖及自动清理仍依赖夸克能力升级，不能隐藏旧文件冒充覆盖。

## 验收与交付

1. **前置实测**：从没有继承 Agent 标识的普通终端启动实际 Agent，执行固定只读任务；在该任务中夸克识别成功，再完成隔离测试目录的授权、上传、下载及校验。不接触真实存档。Codex Mac 链路通过才可交付为可用。
2. **导出与合并测试**：验证只有选定会话的公开消息；混合推理、工具、环境包装、凭据、缺失/截断记录时正确排除或报错；重复同步不膨胀；跨设备分支和更换 Agent 保留来源及消息。
3. **启动与失败测试**：清洁环境下 `npm start` 自动使用绑定；缺失 CLI、登录失效、拒绝授权、离线、任务超时、取消和退出均显示真实状态，本地功能可继续，不遗留无限任务。
4. **云端测试**：对话上传回读、内容变化才上传、半成品与坏哈希不采用、并发分支不丢失。测试目录独立于真实存档目录。
5. **UI 和文档**：README 通用说明首次绑定、预览、普通终端启动、恢复来源、手动同步、解除绑定、额度消耗和修复步骤；更新可执行 Windows 验证文档，未实测的项目明确标注待验证。
6. **回归**：现有两份备份限额、确认删除、显式选择云端来源和覆盖前备份仍通过；自动对话同步不会操作游戏存档。

## 设计审阅记录

首次独立审阅提出三处需要补全：后台消息可能触发同步循环、新设备如何发现同一项目、恢复会话怎样供用户继续交流。本文已按开发者默认选择补全：严格排除运行会话和自动导入消息、固定单项目标识、提供独立的继续对话命令而不新增聊天界面。以上选择连同云端暂存多个修订及模型额度消耗，一并供用户确认。
