# Agent 绑定与对话读取验证

## Windows 打包应用的工作入口

外部 Node.js 无法直接读取 Electron `app.asar` 内的工作脚本。Windows 构建将后台所需的 `.mjs` 模块及继续对话脚本同时放在 `resources/agent-runtime/`，由桌面程序向 AgentManager 提供实际路径；绑定检查、后台任务和继续对话命令均使用这些普通文件。运行时目录仅包含程序代码，不包含授权缓存、本机绑定或对话资料。

62 项自动测试及合成 UI 流程通过，新增测试覆盖绑定后的 worker 路径、继续对话脚本路径及夸克上传后的延迟枚举。构建后的工作模块可由普通 Node.js 导入。

Windows 本机当前项目会话已通过真实后台入口检查并保存绑定。清除继承的宿主身份变量后，打包 EXE 普通启动自动同步成功，返回 `AGENT_STARTUP_OK`；当次合并 150 条公开项目消息、云端 4 个修订。上传后的目录可见性延迟采用最多 6 次查询、间隔 1 秒的有限等待，仍完整下载并核对哈希。游戏存档未上传或覆盖，本机凭据和绑定未加入构建。

## Windows 绑定后的游戏存档发布

实际约 6 MB 的合成存档通过绑定 Agent 发布时，工作进程内的 `tasklist.exe` 检查无法确认宿主游戏状态，导致上传在网络请求前停止。桌面 Service 已在事务恢复和快照生成前检查游戏进程，因此后台发布移除重复的宿主进程查询，仅读取经过身份、路径及内容校验的暂存快照；桌面端的游戏运行拦截保留。

修复后，相同规模的合成存档在真实绑定 Agent 中上传、回读及完成标记发布通过。新增快照和完成标记均采用有限目录可见性等待，不重复上传、不跳过哈希校验。上传错误会自动滚动至可见位置。63 项自动测试及合成 UI 流程通过，真实游戏存档未参与诊断上传。

## 存档操作优先于自动对话同步

启动与定时自动对话同步标记为后台任务。手动云端操作先预留执行入口，再取消并等待自动同步退出；IPC 处理结束或失败时释放入口，期间定时任务不会重新抢占。被中断的公开对话保持待同步状态，可在后续检查中继续。手动绑定、登录及手动对话同步仍按独占操作处理。

界面在后台自动同步期间保持上传和刷新按钮可用，并在上传按钮旁提示状态。66 项测试、合成 UI 流程及 Windows 真实子进程退出检查通过。打包 EXE 在普通启动的实际后台同步期间返回 `BACKGROUND_UPLOAD_AVAILABLE=true`，随后通过界面发起版本刷新并返回 `CLOUD_PRIORITY_SMOKE_OK`，确认前台操作完成且执行入口释放；该检查没有上传或覆盖真实游戏存档。

## 桌面端会话格式兼容修复

本机终端 PATH 中的 Codex CLI 是 `0.144.6`，桌面端随附版本是 `0.166.0-alpha.5.1`。桌面端当前会话的 `history_mode` 是 `paginated`。旧 CLI 的 `thread/read` 返回 `-32601 / paginated_threads is not supported yet`，并非登录、代理或聊天文件损坏。

修复采用官方本地接口：优先发现兼容的桌面端可执行文件，以 `thread/read` 读取元数据，再用 `thread/items/list` 按游标读取全部页。不执行 `thread/resume` 或 `turn/start`，不改写原会话，不需要模型推理。旧格式通过兼容接口读取完整历史。接口不兼容时尝试下一已安装候选版本，不自动升级或替换全局 CLI。

导出器检查会话 ID 与项目目录，只选取公开 `userMessage` 和 `agentMessage`。内部推理、命令、工具输出、系统提示、环境包装等不进入导出。疑似认证材料整条排除；这不是对公开文字绝无敏感信息的保证，上传前仍可查看预览。读取失败、重复游标或超过上限时不生成“部分成功”的新文件。

本项目会话实际读取通过：8 页、102 条公开消息、排除 631 条其他记录，截至本次验证时。导出只写入版本控制忽略的 `.data/project-context/`，未上传云端。数量会随会话继续而变化。

## 自行验证其他设备

在项目目录运行，替换成该设备中明确选定的项目会话 UUID：

```sh
npm run context:export -- --thread <会话UUID>
```

可选 `--cli <Codex可执行文件绝对路径>`、`--cwd <项目目录>`、`--output <本地输出JSON>`。普通终端必须显式指定会话 ID；真正的 Codex 命令环境可以使用当前 `CODEX_THREAD_ID`。此命令不上传、不改动游戏存档、不登录其他账号。

成功结果包含消息数、实际接口路径、读取模式、分页数及 `uploaded: false`。不要把内部会话日志或整个 Agent 配置目录作为导出文件。

Windows 若 PATH 只有 npm 的 `.cmd` 启动垫片，请用 `--cli` 指向实际 `codex.exe`；当前未完成 Windows 实机验收。缺少支持分页的版本时，需要安装兼容 CLI 或使用桌面端随附的接口。

官方参考：[Codex App Server](https://developers.openai.com/codex/app-server)，其中 `thread/turns/list`、`thread/items/list` 用于分页历史，`thread/read includeTurns=true` 对分页历史已弃用。
