# Windows 首次上传验证（原生 PowerShell）

目标：验证同一个 Steam 账号在 Windows 上传所选 Mod 进度，随后由 Mac 接收。本流程以 Windows 为来源举例；工具允许任一端首次上传，由使用者决定方向。Windows 当前未经实机验证；任一步失败请停止在该步骤，不覆盖真实存档。

## 准备

- 使用 64 位 Windows 10/11、Node.js 22+、Steam 和现有 Mod 环境。
- 将项目源代码放到本地普通目录，不能只复制 Mac `.app`。
- **从夸克组件能够识别的真实 Agent 宿主环境执行命令**，如 Codex、Claude Code、Cursor 等；能否在相应版本中识别，需要实际运行 `npm.cmd run agent:check` 检查，再通过界面的连接验证。当前项目只在 Codex 环境完成 Mac 实测，其他宿主仍需验证。夸克官方 1.0.25 公开说明仅支持 Windows WSL，原生路径属于本次待验证目标。本项目用 Node 原生启动，不要求安装 WSL，也不伪造 Agent 标识；如果官方工具拒绝 Windows 或 Agent 环境，记录原错误并停止，不能将此判为“已支持”。
- 先在 Windows 游戏内记录各角色战绩与 Mod 环境，并确认实际档位和启用的 Mod。完全退出游戏。

## 自动检查

在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows-validate.ps1
```

脚本安装项目依赖与固定版本官方组件，运行合成存档测试和只读路径检查；不上传、修改真实存档，不读取凭据。预期：测试全部通过，doctor 显示账号档位摘要且游戏已退出。

若 PowerShell 禁止脚本，也可逐条运行：

```powershell
node --version
npm.cmd ci
npm.cmd run setup:quark
npm.cmd test
npm.cmd run doctor
npm.cmd run agent:check
npm.cmd start
```

预期官方组件能正常运行并识别真实 Agent 环境。出现“不支持平台”“无法识别当前 Agent”或依赖安装失败时，保留报错，不自行添加假环境变量。

## 官方授权与随机文件往返

1. 工具内点击“登录夸克网盘”，在官方网页完成同一个夸克账号的授权。
2. 点击“验证夸克连接”。预期返回“夸克真实上传、完整枚举、下载及 SHA-256 校验通过”。只看到上传完成不算通过。
3. 退出并重新启动工具，再验证连接，检查授权可复用。若授权失效，重新走官方登录，不向聊天粘贴 Token。

## 首次真实上传

1. 选择实际使用的档位。游戏默认目录常见为 `%APPDATA%\SlayTheSpire2\steam\<SteamID>\profile1\saves`；工具也检查账号下 `modded` 子目录。以游戏日志中的实际写入路径和界面进度摘要为准。
2. 选择“Mod 进度”。Mac 后续必须选择相同同步组。若界面摘要仍显示旧进度，不上传，先检查档位与 Mod 路径。
3. 检查本机备份总数，满 2 份时先在管理区删除旧备份，再点击“备份本机进度（本地）”。备份与夸克连通无关。
4. 已确认 Windows 本机最新进度安全后，关闭两端该游戏的 Steam 云。确认游戏版本和 Mod 环境一致，在界面勾选确认项。
5. 点击“上传本机进度”，确认后等待“云端回读校验通过”。刷新版本，确认设备、时间、全部角色战绩及 Mod 摘要正确。不要删除 Steam 云原有资料。
6. 记录该版本的短 ID、同步组和档位，交给 Mac 核对。

## Mac 接收与游戏验收

1. Mac 退出游戏，选择相同账号、档位和 Mod 组，确保备份至少有一个空位；覆盖前会自动备份。
2. 刷新云端，在版本下拉框中选择来源，核对设备、版本 ID 与进度摘要，再点击“下载并覆盖当前存档”，核对确认框后点击“下载并覆盖”。
3. 预期应用成功并给出原进度备份 ID；两端上传始终可由使用者选择。
4. 用一致的 Mod 环境启动游戏并选中对应档位，核实角色战绩与来源电脑一致。**游戏内读回才算跨平台验收通过**。
5. 若仍读旧进度，退出游戏，不继续新局；通过工具恢复备份并检查日志。如果使用了会改变存档路径的 Mod，请结合游戏日志检查其实际路径；本工具不会自动修补这些 Mod。

## 故障验证（合成数据或备份副本）

- 游戏运行时点击备份或应用：应被拒绝。
- 损坏快照：应校验失败且原存档不变（已由 npm test 覆盖）。
- 两端离线各上传不同进度：应出现多个分支，不自动按时间覆盖。
- 断网、云空间不足：不能显示成功；原本机进度保持不变。
- 写入中断：重启时恢复未完成事务；先用合成测试，不在真实游戏存档上模拟断电。

## 结果记录

填写 Windows 版本、Node/Electron 版本、官方 CLI 版本、路径布局、同步组、Windows 上传版本 ID、Mac 游戏内进度、失败步骤与错误信息。不要包含密码、授权码、Token 或 Cookie。

当前云端仍为历史版本模式；整个工具共用 1 份并覆盖上传尚待接入升级，不能把同名自动改名视为覆盖成功。

## Agent 绑定与普通终端重启验证（待 Windows 实机验收）

以下步骤不要求两台设备同时开机。先完成 Node.js、Codex CLI 和本项目安装，使用 `codex login` 直接登录官方账号。若只有 npm 的 `.cmd` 垫片，当前自动探测需要实际 `codex.exe` 位于 PATH；可先使用桌面版随附的兼容 CLI，或把实际二进制所在目录加入本机用户 PATH 后重新打开 PowerShell。不要只把 `.cmd` 改名为 `.exe`。

1. 在本机项目目录执行 `npm.cmd start`，展开“Agent 与项目对话”。填写本机项目目录和明确选中的项目会话 UUID；没有当地会话则点击“新建本机项目会话”。
2. 必要时填写本机 HTTP(S) 代理，先“预览所选项目对话”，核对只显示此项目公开消息，再“绑定并同步项目对话”。账号模型由 CLI 接口查询，不直接复制其他设备的全局配置。
3. 若提示夸克未授权，完成“登录夸克网盘”，再点击“同步项目对话”。成功时记录公开消息数、最近成功时间、云端修订数。
4. 点击“查看已恢复对话”，确认包含来源设备此前的公开项目讨论；不能出现内部推理、工具执行日志、其他项目聊天或认证材料。
5. 关闭窗口，在普通 PowerShell 中重新运行 `npm.cmd start`。预期自动调用真实绑定 CLI 并同步，不依赖伪造的身份变量，也不自动上传或覆盖游戏进度。
6. 使用“复制继续对话命令”，在本机 PowerShell 粘贴运行。预期启动当地会话、读取历史参考；新发的用户消息和相应公开回复会在下一次变化检查中同步，导入提示及后台任务记录不循环上传。
7. 测试断网或取消：界面不能显示新的同步成功时间，待同步内容保留，本地备份仍可使用；恢复网络后手动重试。CLI 登录、读取阶段和云端任务均需检查取消效果。不要在真实游戏存档上制造故障。
8. 测试“解除本机绑定”确认框：本机绑定和工具缓存清理，但原 Agent 会话、游戏进度和云端文件不删除。

记录 CLI 版本、接口兼容性、实际云端往返结果及取消行为；未经以上实测不能将 Windows 标记为支持。macOS 上验证通过不代表 Windows 沙箱、终端与夸克组件行为相同。
