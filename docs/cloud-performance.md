# 云端刷新与上传性能

Mac 已对齐共享实现并完成实测，详细边界见 [Mac 验证记录](mac-validation.md)：66 项测试、隔离 UI、普通终端启动和真实云端刷新通过。一个版本的直接调用冷/热样本为 6694/1270 ms（6/1 条云端命令）；绑定模式从启动到首刷完成为 31.6 秒，包含真实 Agent 的启动开销。

## 实现

- 目录 ID 在当前 Service 会话内复用，避免每次重新定位四层目录。
- 每次刷新仍查询云端目录。已验证的完成标记按目录、文件名、大小和时间等属性缓存 60 秒；新增或变化的摘要重新下载，已删除版本不再显示。
- 夸克的临时 `fid` 每次枚举可能变化，不用于判断内容是否变化；下载使用最新枚举返回的句柄。
- 绑定模式将整次刷新或上传发布合并为一个真实 Agent 任务。上传前的本地事务恢复与快照生成仍在桌面进程执行，后台任务只读取已生成的快照。
- 上传快照及完成标记仍完整回读并校验哈希。应用存档前强制重新读取完成标记，保持原有快照校验与本地备份流程。
- 重新登录、切换执行器或任务失败后清空缓存。跨 Agent 传递的缓存最多 256 KiB，过期项不传递；缓存不持久化。
- 大批处理结果通过任务目录内的独立文件交回，上限 64 MiB，读取后随任务目录清理，避免普通 RPC 结果的 8 MiB 上限截断版本列表。

## 2026-10-31 检查记录

60 项自动测试和合成 UI 流程通过，包括临时句柄轮换、增删版本、过期、损坏标记、执行器变化、批处理任务次数及 9 MiB 结果传递。合成存档的真实夸克上传、应用和备份恢复通过；真实游戏存档未改动。

使用同一合成历史版本、同一 Service 会话，通过真实夸克连接测量：

| 刷新 | 云端命令数 | 耗时 |
| --- | --- | --- |
| 首次，无缓存 | 6 | 4949 ms |
| 紧接着再次刷新 | 1 | 742 ms |

这是单次、一个版本的直接调用样本。绑定模式还包含一次真实 Agent 的启动与执行时间；网络、版本数量及缓存到期均会影响耗时。首次刷新仍需获取历史摘要。

真实 Agent 的整次版本刷新任务与结果文件交回通过（一次任务，空版本列表样本耗时 16829 ms）。Windows x64 应用已重建，构建后的 EXE 本地冒烟返回 `DESKTOP_SMOKE_OK`。

可运行 `node --test tests/refresh-performance.test.mjs tests/save-task.test.mjs tests/agent-runner.test.mjs` 检查请求次数和任务边界；`npm.cmd run test:ui` 检查界面流程。Windows 构建使用 `npm.cmd run pack:windows`。
