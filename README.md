# 尖塔存档桥

通过夸克网盘，在 Windows 和 macOS 之间传递《杀戮尖塔 2》的 Steam 存档。两台电脑无需同时开机，也无需连接同一个局域网。

两端都可以上传进度，由你选择在哪台电脑继续游玩。工具提供存档摘要、手动上传下载、本地备份恢复，以及项目公开对话同步。

游戏存档需要手动上传和应用：退出游戏不会自动上传，打开工具也不会自动覆盖本机进度。项目对话则在完成绑定后，于启动时同步，并每 60 秒检查本地公开消息变化。

## 使用前准备

两台电脑分别准备好：

- 《杀戮尖塔 2》Steam 版，使用同一个 Steam 账号。
- 同一个夸克网盘账号。
- 一致的游戏版本；使用 Mod 时，准备好一致的 Mod 环境。
- 项目源代码或对应操作系统、CPU 架构的应用目录。
- Node.js 22.12 或更高版本。源码启动还需要 npm；Agent 自动绑定与后台任务需要本机安装并登录 Codex CLI，或使用包含兼容 CLI 的桌面端。

两端都先启动一次游戏，生成要使用的本地档位，再完全退出。工具只列出已有档位。

在备份、上传、应用或恢复存档前，先完全退出游戏。在两端 Steam 中打开该游戏的“属性 → 通用”，关闭该游戏的 Steam 云存档选项，再在工具内勾选确认项。本工具不会替你修改 Steam 设置。

如果要取回 Steam 云上的进度，先通过 Steam 完成同步、在游戏内核对并退出游戏，再切换到本工具。Steam 云与夸克是两个独立的存储位置，关闭 Steam 云不会把其中的存档自动导入夸克。

## Windows 使用说明

### 打开应用

保留完整的 `SpireSaveBridge-win32-x64` 应用目录，双击其中的 `SpireSaveBridge.exe`。不要只复制 EXE，旁边的 DLL 和 `resources` 等文件也是运行所需文件。

如果应用位于项目的 `dist` 目录，也可以在项目根目录的 PowerShell 中运行：

```powershell
& .\dist\SpireSaveBridge-win32-x64\SpireSaveBridge.exe
```

应用已包含 Electron。首次打开后，按下文“首次配置”完成本机 Agent 绑定和夸克授权。源码与打包应用的夸克授权目录可能不同，切换启动方式后如提示未授权，请在当前应用内重新授权。

### 从源码安装和启动

安装含 npm 的 Node.js，并确保 `node` 和 `npm.cmd` 可在 PowerShell 中使用。打开项目目录的 PowerShell，执行：

```powershell
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run setup:quark
npm.cmd start
```

`npm.cmd ci` 安装依赖，`setup:quark` 下载并校验官方夸克组件。首次安装或项目依赖更新后执行这两步即可。

日常打开时，在同一项目目录执行：

```powershell
npm.cmd start
```

Windows 使用 `npm.cmd`，可避免 `npm.ps1` 被 PowerShell 执行策略拦截。不需要安装 WSL。

### Windows 路径与常见启动问题

| 项目 | 位置或处理方式 |
| --- | --- |
| 默认游戏存档 | `%APPDATA%\SlayTheSpire2\steam\<SteamID>\profileN\saves` |
| Mod 独立存档 | `%APPDATA%\SlayTheSpire2\steam\<SteamID>\modded\profileN\saves` |
| 本地备份 | `%APPDATA%\SpireSaveBridge\local-backups` |
| Agent 绑定与对话缓存 | `%APPDATA%\SpireSaveBridge\agent` |
| 找不到 `node` 或 `npm.cmd` | 检查 Node.js 安装目录是否已加入 PATH；安装后重新打开 PowerShell |
| 安装出现文件占用或 `EPERM` | 关闭本项目的应用、测试和安装进程后，重新执行 `npm.cmd ci` |
| 后台任务网络超时 | 在“Agent 与项目对话”中填写本机实际 HTTP(S) 代理；系统代理不代表 CLI 已自动使用它 |

### Electron 下载失败时

从源码首次启动时，如果下载 Electron 连接 GitHub 超时，可以在当前 PowerShell 设置下载镜像后重试。下载仍会按依赖包内的 SHA-256 校验值检查：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CUSTOM_DIR = '{{ version }}'
npm.cmd start
```

这些环境变量只对当前终端及其启动的进程生效。

## 首次配置（两端通用）

### 绑定本机 Agent 与项目对话

1. 安装并登录 Codex CLI，或安装包含兼容 CLI 的桌面端。可以在终端执行 `codex login`；界面中的“CLI 官方登录”也会走官方流程，可能打开浏览器等待确认。不要将登录文件、Token 或 Cookie 发到聊天或网盘。
2. 按对应平台的方式打开应用，展开右侧下方“Agent 与项目对话”。
3. 填写“本机项目目录”，它必须与所选开发会话所属目录一致。填写该设备中明确选中的项目会话 UUID。在真实 Codex 环境初次启动时会预填当前 UUID；普通终端不会扫描并抓取其他聊天。
4. 新设备没有项目会话时，点击“新建本机项目会话”，将建立当地会话并填入 UUID，再进行预览。不会因此复制另一台设备的内部会话 ID。
5. 如终端访问 Agent 服务需要代理，在代理栏填入该设备的 `http://127.0.0.1:端口` 等有效地址，不含账号口令。该设置只用于相关子进程，不修改系统代理，也不会上传云端。
6. 点击“预览所选项目对话”，展开“公开对话预览”，核对内容、消息数、实际 CLI 路径与模型。程序优先选用兼容桌面格式的接口，并查询账号可用模型；不会更改全局 CLI 配置。自动绑定使用 Codex 适配器；通过其他 Agent 宿主直接启动的方式见下文。
7. 点击“绑定并同步项目对话”，核对确认框。程序先验证真实 Agent 中的夸克宿主识别，再保存本机绑定、合并云端对话并上传有变化的内容。若夸克尚未授权，待错误返回后使用原有“登录夸克网盘”按钮完成官方授权，再点击“同步项目对话”。
8. 等待管理区显示“项目对话已同步”和最近成功时间。这里的同步不上传或覆盖游戏存档；游戏进度仍需使用原有按钮。

只同步所选项目的公开用户消息与助手回复。内部推理、工具日志、系统指令、环境包装和明显认证字段被排除。过滤不能保证公开文字没有任何敏感内容，因此绑定前应查看预览。后台任务的运行会话不进入项目对话；历史导入及其自动确认也不作为新消息反复上传。

### 日常启动、恢复与继续对话

绑定后，日常按对应平台的方式重新打开应用即可。本地摘要与备份先可用；后台启动绑定的 Agent，同步项目对话。每 60 秒只检查本地变化，无变化不再调用模型上传。一次失败不会无限调用模型重试：修复网络或授权后，点击“同步项目对话”；下一次启动也会重试。

自动对话同步期间仍可点击上传、刷新版本等云端操作。手动操作会先暂停自动同步，存档任务结束后在后续后台检查中继续同步对话。上传按钮下方会显示当前状态；手动配置 Agent 或正在处理其他操作时，先完成或取消该操作。

另一台设备登录同一夸克账号并完成自己的绑定后，会读取固定项目 `spire-save-bridge` 的云端公开对话，不依赖两台电脑同开。点击“查看已恢复对话”可在工具内查看合并内容。点击“复制继续对话命令”，在本机终端粘贴运行；它会使用绑定模型与本机代理，恢复当地会话并要求先读取最新的本地历史参考资料。历史内容不是新的操作授权。两台设备会话 ID 可以不同。

“取消后台任务”会取消本工具启动的读取或执行任务，保留本地待办。“解除本机绑定”经确认后删除工具自己的绑定和对话缓存，不删除原 Agent 会话、游戏进度或云端文件；修改代理、会话来源时先解除绑定再重新预览绑定。

绑定及对话缓存位于 macOS 的 `~/Library/Application Support/SpireSaveBridge/agent/`，Windows 的 `%APPDATA%\SpireSaveBridge\agent\`。路径、代理和登录配置只留当地。打包仅包含夸克分发脚本，不携带开发设备的授权缓存；已构建应用首次使用可能需要单独授权。

### 对话云端保留限制

对话目录为 `STS2-SaveSync/project-context/spire-save-bridge/`，与游戏档位目录分开。对话变化会生成新修订，并回读校验。并发设备的公开消息会合并，旧修订保留在云端。

单修订最多 8 MiB、50000 条消息；目录超过 256 个文件会停止同步并提示整理。达到上限时可在夸克客户端处理旧修订，但应同时保留当前完整的 `.context.json` 与对应 `.ready.json`，不要只删除其中一个。对话按修订保留历史，不会自动删除旧修订。

仅检查本地导出可运行：

```sh
npm run context:export -- --thread <本机项目会话UUID>
```

输出到项目的 `.data/project-context/project-dialogue.json`，不会上传。Windows 使用 `npm.cmd run context:export -- --thread <本机项目会话UUID>`。

### 通过 Agent 宿主直接启动

普通终端或双击应用启动时，使用上述本机绑定方式。绑定后，程序调用本机真实 CLI 执行云端任务，可能消耗账号额度。

也可以由夸克组件支持的真实 Agent 宿主启动应用，继承其运行环境并直接调用夸克组件。启动前在同一命令上下文执行 `npm run agent:check`（Windows 使用 `npm.cmd run agent:check`），确认宿主识别结果，再打开应用完成夸克授权。仅在旁边打开 Agent 不会让普通终端自动获得其环境。

切换宿主或电脑后，应在当地重新完成所需授权。不要通过添加虚假的环境标识绕过宿主识别。

### 本地备份与夸克版本的区别

| 操作                 | 保存位置与结果                                                   |
| -------------------- | ---------------------------------------------------------------- |
| 备份本机进度（本地） | 在当前电脑保存快照并返回备份 ID，不上传夸克，也不修改游戏进度    |
| 上传本机进度         | 在夸克保存独立云端版本，供另一台电脑获取，不修改本机游戏进度     |
| 下载并覆盖当前存档   | 从夸克下载所选版本；先在本机保存覆盖前的备份，再替换所选档位     |
| 恢复本地备份         | 使用当前电脑上的备份恢复进度，恢复前再次本地备份，不自动上传夸克 |

本地备份用来撤销误操作；跨电脑传递进度需要上传夸克。覆盖前的本地备份不会自动变成云端版本。

#### 本地备份数量与云端历史

整台设备的所有账号、档位和原版/Mod 同步组合计最多 **2 份本地备份**。手动备份、覆盖前自动备份和恢复前自动备份共用名额。达到上限后，在管理区核对时间与摘要，删除一份不需要的备份，再执行新的备份、覆盖或恢复。

旧版备份也计入总数；工具不会自动清理旧备份。删除只影响所选本机备份，不修改当前游戏存档或夸克文件。

**云端按历史版本保存。** 每次上传都会新增版本，旧云端文件不会自动清理。请在接收电脑上明确选择本次要应用的版本。

### 1. 选择档位和同步组

1. 在左侧“Steam 档位”下拉框中选择要处理的档位。
2. 检查选项中的目录类型：“游戏默认目录”或“Mod 独立目录”。它们是本机发现的候选目录，具体使用哪一个要与游戏实际读写的目录一致。
3. 在“本次同步组”中选择“原版进度”或“Mod 进度”。**界面默认选中“Mod 进度”，首次使用时请主动核对。**
4. 查看右侧角色战绩和进度摘要，确认选中的是你希望处理的进度。

同步组是工具的版本分类，不会安装、启用、禁用或切换游戏 Mod。部分路径 Mod 会让游戏默认目录承载 Mod 进度，因此不能只靠目录名称判断，应结合游戏内进度和日志核对。

两台电脑传递同一份进度时，需要选择相同的 Steam 账号、档位和同步组。切换档位或同步组后，点击“刷新版本”重新查询云端。

#### 如何理解摘要

- **角色战绩**：分别列出各角色的胜利、失败、胜率和最高进阶，包含可识别的 Mod 角色；随机角色占位记录不计为独立角色。
- **总战绩**：汇总摘要中角色的胜利和失败次数。
- **累计时长**：读取该档位存档中的累计游戏时长。
- **存档更新**：本机存档文件的修改时间；云端版本保存上传时记录的时间信息。
- **Mod 已加载 / 检测到**：来自上次游戏启动日志，同时展示日志时间。
- **上次启动版本**：读取游戏启动日志中的版本号。

Mod 信息描述的是该电脑上次启动游戏的环境，不是对所选档位当前兼容性的保证。没有对应记录时显示“未记录”或“—”，不会把未知数据补成零。较早上传的版本可能没有完整摘要。

文件时间会受到复制、下载和应用操作影响，不能只按时间判断哪份进度更合适。请结合角色战绩、来源设备、同步组和游戏内记录自行选择。

### 2. 登录夸克并检查连接

每台电脑首次使用时分别完成：

1. 点击“登录夸克网盘”。
2. 在自动打开的官方网页中登录夸克账号，并核对页面显示的授权范围后完成授权。
3. 回到工具，等待状态区域显示“夸克授权完成”。不需要向聊天或工具粘贴密码、Cookie 或 Token。
4. 点击“验证夸克连接”。
5. 等待状态区域显示上传、完整枚举、下载和 SHA-256 校验通过。

连接验证使用随机测试文本，不读取游戏存档。测试文件保存在夸克的 `STS2-SaveSync-Validation` 目录中，不会自动清理。

授权完成后通常可以在后续启动时复用；提示未授权或授权过期时，再点击“登录夸克网盘”重新授权。当前界面没有独立的注销或撤销授权按钮，授权管理由夸克官方流程处理。

### 3. 上传本机进度

在你选择作为来源的那台电脑上操作，macOS 和 Windows 步骤相同：

1. 在游戏中确认要保留的进度，然后完全退出游戏。
2. 打开工具，选择正确的“Steam 档位”和“本次同步组”。
3. 核对角色战绩、存档时间和环境信息，确认它是本次要上传的版本。
4. 检查左侧备份数量，满额时先在管理区删除旧备份。点击“备份本机进度（本地）”，等待“本地备份已保存”，记录提示中的备份 ID。这一步不需要夸克登录，也不需要勾选同步确认项，但需要游戏已经退出。
5. 完成夸克授权和连接验证。
6. 关闭两端该游戏的 Steam 云，确认游戏版本与 Mod 环境一致，然后勾选左侧“我已关闭两端 Steam 云，确认游戏版本与 Mod 环境一致”。
7. 点击“上传本机进度”。在弹出的确认框中核对操作，点击“继续”；选择“取消”则不执行上传。
8. 等待状态区域显示“上传完成，云端回读校验通过”。仅看到“正在处理”或文件开始传输，不代表上传已经完成。
9. 上传成功后，工具会自动刷新云端列表及覆盖来源下拉框。核对本次上传的设备、时间、版本短 ID 和进度摘要；如刷新失败，可点击“刷新版本”重试。覆盖来源仍需手动选择。

上传会创建独立版本，不会替换本机游戏存档，也不会自动应用到另一台电脑。另一台电脑之后联网并打开工具即可获取，无需同时运行。

### 4. 选择云端版本并应用到本机

1. 完全退出接收电脑上的游戏。
2. 打开工具，选择对应的 Steam 档位和相同的同步组。
3. 确保本机备份至少有一个空位。覆盖前会自动保存当前进度，无需再手动创建重复备份；满额时先在管理区删除一份。
4. 登录同一个夸克账号，点击“刷新版本”。
5. 在“选择要覆盖到本机的云端版本”下拉框中明确选择来源，或点击版本列表中的“选为覆盖来源”。刷新不会默认选中任何版本。
6. 查看下拉框下方的预览，核对覆盖目标、来源设备、上传时间、短 ID、总战绩和 Mod 信息；展开“查看所有角色战绩”，与本机档位概览比较。
7. 关闭两端该游戏的 Steam 云，确认游戏版本和 Mod 环境一致，勾选左侧确认项。
8. 点击“下载并覆盖当前存档”。在弹出的确认框中核对目标目录、档位、同步组和所选版本 ID，再点击“下载并覆盖”；点击“取消”不执行覆盖。
9. 等待覆盖成功提示。工具会先下载校验，再自动备份本机被管理的存档，最后应用所选版本；成功提示会给出原进度的备份 ID，请保留该 ID。
10. 启动游戏，选择对应档位，核对进度和角色战绩。确认读取正确后，再继续游玩。

“下载并覆盖当前存档”会改变所选档位的本地进度，不是单纯下载一个存档包。**云端版本时间更新并不代表必须应用，选择权始终在使用者。**

切换档位、切换同步组或重新刷新后，需要重新选择云端版本，旧选择不能继续用于覆盖。

应用后如果游戏仍显示旧进度，先退出游戏，通过备份恢复并检查实际读取的档位、目录及 Mod 环境。本工具不会自动修补影响存档路径的 Mod。

### 日常换机流程

每次从一台电脑切换到另一台电脑时，执行同一套流程：

1. 在当前电脑完全退出游戏。
2. 打开工具，核对本机档位摘要，上传本次要保留的进度并等待成功。
3. 在另一台电脑退出游戏、打开工具，选择相同档位和同步组，刷新云端版本。
4. 对比本机与云端摘要，选择要继续的版本并下载应用。
5. 在游戏内确认进度，再继续游玩。

下一次换回原电脑时，交换来源与接收方即可。工具不会规定哪一端必须优先，也不会根据操作系统或首次同步状态阻止上传。

#### 两端都产生了新进度时

如果两端分别离线游玩，上传后可能形成多个云端分支。界面会提示存在多个分支，保留这些完整版本，由你决定应用哪一个。

工具不合并角色解锁、战绩或进行中的对局，也不会因为某个版本上传时间更晚就自动覆盖其他版本。选择一份完整存档后，另一份仍作为历史版本保留。

## 恢复本地备份

适用于应用了错误版本，或希望回到某次本机备份的情况：

1. 完全退出游戏。
2. 选择备份对应的“Steam 档位”和“本次同步组”。
3. 展开“管理与恢复本地备份（本机最多 2 份）”，点击“查看备份”，列表展示全部已识别档位和同步组的本机备份。
4. 根据时间、档位、同步组、备份 ID 和角色摘要选择来源。若要撤销刚才的覆盖，可核对成功提示中的备份 ID。满额时先删除另一份不需要的备份，为恢复前备份留出空位。
5. 确认 Steam 云已关闭、游戏版本与 Mod 环境一致，勾选左侧确认项。
6. 点击“恢复此备份”，在确认框中选择“继续”。只有与当前账号、档位和同步组匹配且未损坏的备份才能恢复。
7. 等待“本地备份已恢复”，再启动游戏核对进度。

恢复操作也会先备份被替换的本机进度。恢复完成后不会自动上传夸克；是否将恢复后的进度另行上传，由你决定。

释放名额时，点击对应条目的“删除此备份”，核对确认框后删除。损坏备份也计入数量，可删除但不能恢复。列表按记录时间排序，旧版缺失字段显示未知。

本地备份不会自动同步到另一台电脑。使用新版前请退出旧版，避免旧版继续产生不受新规则管理的备份。

## 数据范围与保存位置

### 游戏存档范围

工具自动发现以下候选路径中的档位：

| 系统    | 候选账号目录                                                   |
| ------- | -------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/SlayTheSpire2/steam/<SteamID>/` |
| Windows | `%APPDATA%\SlayTheSpire2\steam\<SteamID>\`                     |

在账号目录内检查 `profile1`、`profile2`、`profile3` 下的 `saves`，以及 `modded/profileN/saves`。只有带有 `progress.save` 或未完成恢复事务记录的档位才会被发现。当前界面没有手动选择任意存档目录的入口。

每份快照包含所选 `saves` 目录中的 `.save`、`.save.backup` 和 `history/` 文件，排除 `prefs.save` 及其备份。账号级 `profile.save`、显示和输入偏好、日志、缓存、重放缓存及 Mod 本体不传输；应用后需要在游戏中选择对应档位。

单份存档的被管理文件总量上限为 64 MiB。工具会检查路径、文件大小和 SHA-256；遇到未知文件类型、符号链接或校验失败时停止操作。应用过程中发生错误时尝试回滚，启动时也会检查未完成的恢复事务。

### 工具数据目录

| 启动方式         | 保存位置                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| 从项目源代码启动 | `<项目目录>/.data/desktop`                                                                                         |
| 从打包应用启动   | Electron 用户数据目录，位于 macOS 的 `~/Library/Application Support/` 或 Windows 的 `%APPDATA%` 下，以应用名称命名 |

源代码和打包启动仍可能使用不同的传输缓存及同步记录目录；新版桌面应用的本地备份统一存放，不因启动方式而增加名额：

| 系统    | 统一备份目录                                                   |
| ------- | -------------------------------------------------------------- |
| macOS   | `~/Library/Application Support/SpireSaveBridge/local-backups/` |
| Windows | `%APPDATA%\SpireSaveBridge\local-backups\`                     |

文件名为 `<备份 ID>.json`，账号、档位和同步组保存在文件内部。新备份共用此目录的 2 个名额；识别到的旧版备份保持原位，也列入管理区并计数，不自动搬移或删除。

### 云端目录

正式存档版本保存在工具创建的 `STS2-SaveSync` 目录下，再按 Steam 账号、档位和同步组分层；上层位置由夸克官方组件的默认目录规则决定。

每个完整版本包含快照文件和完成标记。文件名中的版本 ID 用于将两者配对，工具只列出已发布的完整版本。日常通过界面操作即可，保留这些文件的名称和配对关系。

夸克授权由官方组件管理并按 Agent 隔离，不随项目源码、存档快照或打包应用分发。迁移到另一台电脑时，应在该电脑重新完成授权。

## 常见问题

| 情况                               | 处理方法                                                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| “Steam 档位”为空                   | 确认当前系统已经有该游戏的本地存档；退出游戏后重新启动工具。检查是否使用了自定义路径或工具尚未支持的目录布局。           |
| 摘要与游戏内进度不同               | 核对实际档位、默认目录与 Mod 独立目录；同步组不会切换游戏读取路径。修改游戏进度后，退出游戏并重新打开工具获取摘要。      |
| “未授权”或授权过期                 | 点击“登录夸克网盘”，重新完成官方网页授权，再执行原操作。                                                                 |
| “无法识别当前 Agent 环境”          | 在真实受支持宿主的命令上下文运行 `npm run agent:check`，再于同一上下文启动工具并验证夸克连接；并非只能使用 Codex。       |
| “下载并覆盖当前存档”按钮不可用     | 先选择本机档位、刷新云端版本，并在下拉框中明确选择来源；任务执行期间也会暂时禁用。                                       |
| 上传、应用或恢复时要求确认         | 完成两端 Steam 云设置及游戏、Mod 环境核对后，勾选左侧确认项，再重试。                                                    |
| 游戏仍在运行，或无法确认游戏状态   | 完全退出游戏及相关游戏进程，再重试。                                                                                     |
| 云端版本列表为空                   | 核对夸克账号、Steam 账号、档位和同步组，点击“刷新版本”；确认来源电脑的上传已经成功。Steam 云上的版本不会自动出现在这里。 |
| 版本没有 Mod 数或完整战绩          | 该版本可能没有记录这些字段；Mod 数也可能因为缺少启动日志而未知。                                                         |
| 网络失败、超时或网盘空间不足       | 处理网络或容量问题后再操作；以工具最终的成功提示为准，不只看传输是否开始。                                               |
| 存档超过大小限制或出现不支持的文件 | 根据错误确认具体文件，保留原始存档再排查；当前界面不能调整文件范围或大小上限。                                           |
| 下载校验失败                       | 保留当前本机存档，重新刷新版本并重试；持续失败时记录版本 ID 与错误信息。                                                 |
| 应用后游戏仍读取旧进度             | 退出游戏，核对档位、路径和 Mod 环境，必要时恢复本地备份。                                                                |
| 本机备份达到上限                   | 在管理区核对时间和摘要，删除一份不再需要的备份后操作；覆盖前自动备份也需名额。                                           |
| 找不到之前的备份                   | 点击“查看备份”，检查统一备份目录和已知旧版应用/项目目录；工具不会扫描整台电脑寻找未知旧版目录。                          |

报告问题时，可提供操作系统、工具版本、失败步骤、版本或备份 ID、错误提示，以及不含凭据的摘要信息。不要附带密码、Cookie、Token 或授权码。

## 开发与构建

在项目根目录运行：

| 命令                      | 作用                                                  |
| ------------------------- | ----------------------------------------------------- |
| `npm test`                | 运行自动测试，使用合成数据和临时目录                  |
| `npm run test:ui`         | 验证版本选择和覆盖按钮流程，只使用合成界面数据        |
| `npm run agent:check`     | 只检查官方夸克组件的宿主识别结果，不登录或传输文件    |
| `npm run doctor`          | 只读检查本机档位摘要和游戏进程                        |
| `npm run probe:cloud`     | 用随机文本验证真实夸克上传、枚举、下载和哈希校验      |
| `npm run probe:roundtrip` | 用合成存档验证真实云端上传、应用和备份恢复            |
| `npm run pack:mac`        | 生成 macOS 应用，架构跟随构建主机                   |
| `npm run pack:windows`    | 生成 Windows x64 应用 |

Windows PowerShell 中可以使用 `npm.cmd` 替代 `npm`。构建前需要完成依赖安装和 `setup:quark`。构建输出位于 `dist`，云端验证文件会保留在 `STS2-SaveSync-Validation` 中。

开发资料：[Windows 开发检查](docs/windows-validation.md)、[macOS 开发检查](docs/mac-validation.md)、[Agent 接入说明](docs/agent-validation.md)。
